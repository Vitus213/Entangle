## 🧪 测试场景

### 场景 1: 单用户 CRDT 初始化

**目标**: 验证文档能正确从 CRDT 状态初始化

**步骤**:
1. 登录系统（使用 demo@example.com / demo123）
2. 打开一个现有文档
3. 打开浏览器开发者工具（F12）
4. 查看控制台输出

**预期结果**:
- ✅ 控制台显示 "从 CRDT 状态初始化文档" 或 "CRDT 管理器已初始化"
- ✅ 文档内容正确显示
- ✅ 无错误信息

### 场景 2: 本地编辑同步到服务器

**目标**: 验证本地编辑能通过 CRDT 同步

**步骤**:
1. 在编辑器中输入一些文本
2. 等待 500ms（防抖延迟）
3. 观察控制台和同步状态指示器

**预期结果**:
- ✅ 控制台显示 "CRDT 更新已发送"
- ✅ 同步状态从 "正在同步..." 变为 "已同步"
- ✅ WebSocket 连接保持活跃

### 场景 3: 多用户实时协作

**目标**: 验证两个用户能同时编辑并自动同步

**步骤**:
1. 打开两个浏览器窗口（或使用隐身模式）
2. 两个窗口都登录（可以使用同一账号）
3. 两个窗口打开同一个文档
4. 在窗口 A 输入文本 "Hello from A"
5. 观察窗口 B 是否自动显示

**预期结果**:
- ✅ 窗口 A 编辑后，窗口 B 自动更新
- ✅ 窗口 B 显示 "Hello from A"
- ✅ 两个窗口的在线用户列表都显示对方
- ✅ 无内容冲突或丢失

### 场景 4: 并发编辑冲突解决

**目标**: 验证 CRDT 能自动解决冲突

**步骤**:
1. 两个浏览器窗口打开同一文档
2. 窗口 A 在文档开头输入 "AAA"
3. 同时窗口 B 在文档开头输入 "BBB"
4. 等待同步完成

**预期结果**:
- ✅ 两个窗口最终内容一致
- ✅ 内容包含 "AAA" 和 "BBB"（顺序由 CRDT 决定）
- ✅ 无错误或异常

### 场景 5: 断线重连

**目标**: 验证 WebSocket 断开后能继续工作

**步骤**:
1. 打开一个文档
2. 在浏览器开发者工具中模拟网络断开
3. 编辑文档
4. 恢复网络连接

**预期结果**:
- ✅ 断网时显示 "未连接" 状态
- ✅ 恢复网络后自动重连
- ✅ 离线编辑的内容能同步到服务器

## 🔍 调试技巧

### 1. 查看 CRDT 状态

在浏览器控制台执行:
```javascript
// 查看当前文档的 CRDT 状态大小
console.log("CRDT state:", crdt_manager);
```

### 2. 查看 WebSocket 消息

在开发者工具的 Network 标签页:
1. 过滤 WS (WebSocket)
2. 点击 WebSocket 连接
3. 查看 Messages 标签页
4. 观察发送和接收的消息

**消息示例**:
```json
// 发送 CRDT 更新
{
  "type": "sync",
  "update": "01a2b3c4..."
}

// 接收用户加入
{
  "type": "user_joined",
  "user_id": "uuid",
  "nickname": "张三"
}
```

### 3. 查看后端日志

后端运行时会输出详细日志:
```
[INFO] 用户 uuid 连接到文档 uuid
[DEBUG] 接收到 CRDT 更新: 256 bytes
[INFO] CRDT 状态已持久化
```

## 🐛 常见问题排查

### 问题 1: 文档无法加载

**症状**: 打开文档后一直显示 "加载中..."

**排查步骤**:
1. 检查后端服务器是否运行
2. 检查浏览器控制台是否有错误
3. 检查网络请求是否成功 (Network 标签页)

**可能原因**:
- 后端服务器未启动
- 数据库连接失败
- 文档 ID 不存在

### 问题 2: WebSocket 无法连接

**症状**: 在线用户列表显示 "未连接"

**排查步骤**:
1. 检查控制台是否有 WebSocket 错误
2. 检查后端是否支持 WebSocket
3. 检查 URL 是否正确 (ws://127.0.0.1:3000/ws/documents/...)

**可能原因**:
- Token 未正确传递
- 后端 WebSocket 端点未启动
- 防火墙阻止 WebSocket

### 问题 3: CRDT 更新失败

**症状**: 控制台显示 "应用 CRDT 更新失败"

**排查步骤**:
1. 检查详细错误信息
2. 查看发送的 update 数据是否有效
3. 检查十六进制编解码是否正确

**可能原因**:
- CRDT 状态损坏
- 编解码错误
- yrs 版本不兼容

### 问题 4: 内容不同步

**症状**: 窗口 A 编辑，窗口 B 不更新

**排查步骤**:
1. 检查两个窗口的 WebSocket 连接状态
2. 查看后端是否收到并广播了更新
3. 检查防抖延迟（默认 500ms）

**可能原因**:
- WebSocket 未连接
- 后端广播机制故障
- 浏览器标签页被挂起

## 🚀 下一步优化

完成基本测试后，可以考虑以下优化：

1. **增量更新**: 只发送文档的变化部分，而不是完整状态
2. **压缩**: 对大型 CRDT 更新使用 gzip 压缩
3. **批处理**: 将多个小更新合并成一个大更新
4. **光标同步**: 实现 Awareness 状态，显示其他用户的光标位置
5. **冲突可视化**: 当发生并发编辑时，高亮显示冲突区域
